# Hybrid Pipeline 개발 보고서

> 시험지 AI 자동 검수 파이프라인 — 설계·실험·결과 정리  
> 대상 파일: `(20260526) 테스트 자료V2_정보보호능력검정_정보보호개요 및 정보보호윤리(O,X 통합).hwp`

---

## 1. 개발 배경 및 목표

정보보호능력검정 시험지 제작 과정에서 오타·누락·편집 흔적 등 20가지 오류 유형(A01~A20)을 LLM으로 자동 탐지하는 파이프라인을 구축한다. 핵심 제약:

- **폐쇄망 환경**: 외부 API(ChatGPT 등) 사용 불가, 로컬 LLM(EXAONE-3.5-32B, lm-studio)만 사용
- **HWP 파싱**: kordoc CLI(Node.js) subprocess로 HWP → IRBlock[] → `## N.` 형식 MD 변환
- **비용 효율**: per-type 방식(600 LLM 호출/문항세트) 대비 호출 수 절감

---

## 2. 파이프라인 진화 과정

### 2-1. Phase 1: per-type (기준선)

20개 유형 프롬프트 × 30문항 = **600 LLM 호출**

- 각 유형별 전용 프롬프트로 문항 1개씩 독립 처리
- 탐지 건수: **52건 / 23문항**
- 문제: 동일 오류를 여러 유형이 중복 탐지, 오탐 다수

### 2-2. Phase 2: Grouped (그룹화 실험)

20개 유형을 5개 그룹으로 통합 → **150 LLM 호출 (75% 절감)**

| 그룹 | 유형 | 일치율(v2) |
|------|------|-----------|
| G1 글자·표기 | A02,A04,A05,A06,A16 | 89.6% |
| G2 문항 구조 | A01,A03,A10,A13,A15,A17,A18 | 91.1% |
| G3 문장 품질 | A07,A08 | **53.3%** ← 문제 |
| G4 법령·도메인 | A09,A19,A20 | 94.3% |
| G5 편집·출판 | A11,A12,A14 | 98.9% |

**핵심 발견**: G3에서 A08(어색한 문장)이 거의 전 문항에 오탐 폭발(20건+). A07·A08을 묶으면 기준이 느슨해짐. 그룹화만으로는 정밀도 확보 불가.

### 2-3. Phase 3: Hybrid (최종 채택)

데이터 기반으로 유형별 최적 처리 방식을 3레이어로 분리.

## 3. 최종 하이브리드 파이프라인 구조

```
입력 MD 파일
     │
     ▼
Layer 0: 코드 처리 ──── A01,A03,A13,A15,A17,A18 (6개)
     │                  규칙 기반, 0 LLM 호출, 즉각
     ▼
Layer 1: 그룹 LLM ───── G1[A04,A05,A06] / G4[A09,A20] / G5[A11,A14]
     │                  90 LLM 호출 (3그룹 × 30문항)
     ▼
Layer 2: per-type LLM ─ A02,A07,A08,A10,A12,A16,A19,A21 (8개)
     │                  240 LLM 호출
     ▼
후처리 필터 ─────────── 오탐 8가지 규칙 제거
     │
     ▼
merged_filtered.json
```

**총 LLM 호출: 330회 (기존 600 대비 45% 절감)**

### 레이어별 분류 근거 (3방향 비교 데이터 기반)

| 레이어 | 분류 기준 | 포함 유형 |
|--------|---------|---------|
| L0 코드 | 규칙 기반 탐지 가능, grouped 100% 미탐 | A01,A03,A13,A15,A17,A18 |
| L1 그룹 | grouped 일치율 67~100%, 안정적 | A04,A05,A06,A09,A11,A14,A20 |
| L2 per-type | grouped 미탐 빈발 or 경계 혼동 심함 | A02,A07,A08,A10,A12,A16,A19,A21 |

**G1에서 제외한 유형**: A02(67% 미탐), A16(83% 미탐) — 경계 혼동이 A04와 심해서 per-type 이동  
**G4에서 제외한 유형**: A19(100% 미탐) — per-type 이동  
**G5에서 제외한 유형**: A12(A11과 오분류 빈발) — per-type 이동

## 4. A21 단어 교체 오류 신설

### 신설 배경

기존 20개 유형에서 커버하지 못하는 오류 유형 발견:
- `비밀번호는 주기적으로 **금지**` → `변경`이 맞음
- `개인정보는 **최대한** 수집` → `최소한`이 맞음

자모 변형(A02)도 아니고, 맞춤법(A04)도 아닌 **사전에 있는 단어가 문맥상 반대/불가 의미로 교체된 경우**.

### A21 정의

```
단어 교체 오류 = 표준국어대사전 등재어이나,
  문맥상 의도한 단어와 의미가 반대이거나 논리적으로 성립 불가하고,
  교정 단어가 1개로 명확히 특정되는 경우
```

**인접 유형과의 경계**:
- vs A02: A02는 자모 변형으로 사전 미등재, A21은 사전 등재어
- vs A08: A08은 문장 구조/호응 어색함, A21은 특정 단어 하나의 의미 교체
- 선택지 텍스트의 내용적 오답(정상 문항 구조)은 A21 아님

### V2 파일 A21 탐지 결과

| 문항 | 탐지 내용 | 판정 |
|------|---------|------|
| Q19 `최대한의 개인정보를` | 개보법 원칙은 **최소한** 수집 | ✅ 정탐 |
| Q28 `주기적으로 금지` | 보안 수칙은 주기적으로 **변경** | ✅ 정탐 |
| Q21 `신분이 드러나지 않는다는` | 빈칸 문항(익명성 자리), 오류 없음 | ❌ 오탐 |
| Q29 `위치정보는 최대한 공유한다` | 의도적 오답 선택지, A21 대상 아님 | ❌ 오탐 |
| Q06 `마 이 데 이 터` | A06/A16과 중복 탐지 | ❌ 중복 |

→ **A21 프롬프트 추가 개선 필요**: 빈칸 문항 지문·오답 선택지 제외 명시

## 5. 후처리 필터 5가지

`src/postprocess.py` 구현. `merged.json` → `merged_filtered.json` 생성.

| 필터 | 규칙 | 제거 케이스 |
|------|------|-----------|
| F1 | A06 탐지 + 같은 문항에 A02도 탐지 + original 겹침 | `외뷰`를 A06(띄어쓰기)으로 오분류 |
| F2 | A11 탐지 + 같은 문항에 A12도 탐지 | `[폐기][해설부족]` A11 중복 탐지 |
| F3 | A06의 original에 `|` 포함 | 신문기사 `|` 기호를 띄어쓰기 오류로 오인 |
| F4 | A02의 suspected에 "의미", "문맥", "사전에 있는" 포함 | 사전 등재어를 A02로 오분류 |
| F5 | A02/A16에서 original 단어↔suggested 단어 음절 공유 없음 | `금지`↔`변경` 같은 의미 교체를 A02/A16으로 오분류 |

**V2 파일 기준 8건 오탐 제거**:
`Q02-A06`, `Q06-A06`, `Q12-A11`, `Q19-A02`, `Q22-A06`, `Q24-A16`, `Q28-A02`, `Q28-A16`

## 7. 성능 비교 요약

| 방식 | LLM 호출 | 문항 재현율 | 정밀도 |
|------|---------|-----------|-------|
| per-type 전체 | 600 | 100% (기준) | 중간 (오탐 多) |
| grouped-v2 단독 | 150 | 65% | 높음 |
| **Hybrid (최종)** | **330** | **~90%+** | **높음** |

**Hybrid 특이사항**:
- Layer 0(코드) 구조 오류: per-type보다 정확 (오탐 없음)
- 법령 조항 오류(A20) 미탐 — **추후 법령 RAG 연동으로 개선 예정**

---

## 8. 남은 개선 과제

| 우선순위 | 과제 | 방향 |
|---------|------|------|
| 높음 | **법령 조항 오류(A20) 미탐** | 법령 RAG 연동 (A09, A19, A20 정밀화) |
| 중간 | **A21 오탐 축소** | 빈칸 문항 지문·오답 선택지 제외 로직 강화 |
| 중간 | **Q28 A06/A08/A10 오탐 잔존** | F1 필터 확장 또는 A21 detected 시 A06/A08/A10 제거 |
| 낮음 | **A08 신뢰도 향상** | 문장 호응 오류 few-shot 다양화 |

## 9. 파일 구조

```
cert-poc/
├── src/
│   ├── hwp_parser.py         # HWP → MD 변환 (kordoc subprocess)
│   ├── code_checker.py       # Layer 0: 규칙 기반 (A01,A03,A13,A15,A17,A18)
│   ├── hybrid_run.py         # 3레이어 통합 실행
│   ├── group_run.py          # 그룹 실험용 러너
│   ├── full_run.py           # per-type 러너 (기준선)
│   ├── postprocess.py        # 후처리 필터 (F1~F5)
│   └── compare_results.py    # per-type vs grouped vs hybrid 비교 분석
│
├── prompts/
│   ├── per-type/             # A01~A21 개별 프롬프트
│   ├── grouped/              # 실험용 그룹 프롬프트 (G1~G5)
│   └── hybrid/               # 최종 그룹 프롬프트 (G1,G4,G5 경량화)
│       ├── MANIFEST.md       # 레이어 분류 기준 문서
│       ├── G1_typo_spelling.md   # A04,A05,A06
│       ├── G4_legal_domain.md    # A09,A20
│       └── G5_editorial.md       # A11,A14
│
└── results/
    ├── v2_pertype/           # per-type 기준선 결과
    ├── v2_grouped/           # grouped-v1 결과
    ├── v2_grouped_v2/        # grouped-v2 결과
    └── hybrid_v2/            # 최종 hybrid 결과
        ├── layer0/           # 코드 검사 결과
        ├── layer1/           # 그룹 LLM 결과
        ├── layer2/           # per-type LLM 결과
        ├── merged.json       # 병합 (필터 전)
        └── merged_filtered.json  # 최종 결과 (필터 후)
```

## 10. 실행 명령어

```bash
# HWP → MD 변환
python src/hwp_parser.py "data/시험지.hwp"

# Hybrid 전체 실행
python src/hybrid_run.py --input "data/시험지.md" --outdir "results/hybrid_결과"

# 특정 문항만 재실행 (기존 결과 유지, 해당 문항만 갱신)
python src/hybrid_run.py --input "data/시험지.md" --outdir "results/hybrid_결과" --q 13 --reset

# 후처리 필터 단독 실행
python src/postprocess.py results/hybrid_결과

# per-type vs grouped vs hybrid 3방향 비교
python src/compare_results.py --three-way
```
