# 시험지 AI 자동 검수 파이프라인

> 정보보호능력검정 시험 문제지를 AI가 자동으로 읽고, 오타·누락·오류를 찾아주는 시스템입니다.

---

## 이 시스템이 하는 일

시험지를 만들다 보면 아래와 같은 실수가 생깁니다.

| 실수 유형 | 예시 |
|---------|------|
| 오타 | `외부 업체` → `외뷰 업체` |
| 선택지 번호 중복 | ①번이 두 번 나옴 |
| 법령명 오기 | `정보통신망 사용촉진` (→ `이용촉진`이 맞음) |
| 선택지 텍스트 누락 | ①번 기호만 있고 내용이 없음 |
| 편집 메모 미삭제 | `[검토필요]` 태그가 그대로 남아있음 |
| 지문 통째 누락 | "다음 문장을 읽고"라고 했는데 지문이 없음 |

이런 오류를 사람이 일일이 찾으면 시간이 많이 걸리고, 피로해지면 놓치기도 쉽습니다.  
**이 시스템은 HWP 파일을 받아서 21가지 오류 유형을 자동으로 검사하고 결과를 알려줍니다.**

---

## 전체 흐름

```
HWP 파일
   │
   ▼
① 문서 파싱 ─── HWP를 읽기 좋은 텍스트(MD) 형식으로 변환
   │
   ▼
② AI 검수 ────── 3단계로 나눠 오류를 탐지
   │
   ▼
③ 결과 저장 ─── 문항별·유형별 JSON 파일로 저장
```

---

## AI 검수의 3단계 구조

오류 종류에 따라 가장 빠르고 정확한 방법을 선택합니다.

```
┌──────────────────────────────────────────────────────────┐
│  1단계: 규칙 검사 (즉각, 무료)                             │
│  컴퓨터가 수식으로 바로 판단할 수 있는 구조 오류             │
│  → 선택지 개수 부족, 번호 중복, 지문 통째 없음 등 6가지     │
└──────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────┐
│  2단계: AI 묶음 검사 (90회 호출)                           │
│  비슷한 성격의 오류를 AI가 한꺼번에 검사                    │
│  → 맞춤법·영어 오자·띄어쓰기 / 법령명 오류 / 편집 흔적      │
└──────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────┐
│  3단계: AI 정밀 검사 (240회 호출)                          │
│  오류 유형별로 전용 프롬프트를 써서 정밀하게 검사            │
│  → 오자, 탈자, 법령 기호 누락, 낙서(편집 메모) 등 8가지     │
└──────────────────────────────────────────────────────────┘
                          │
                          ▼
              결과 병합 → 최종 리포트
```

---

## 탐지 대상 오류 21가지

### 1단계 — 규칙으로 바로 잡아냄 (코드)

| 코드 | 오류 이름 | 예시 |
|------|---------|------|
| A01 | 보기 중복 | ①번과 ③번 내용이 똑같음 |
| A03 | 보기 개수 부족 | ①②④는 있는데 ③이 없음 |
| A13 | 보기 번호 중복 | ③번이 두 개 나옴 |
| A15 | 보기 내용 없음 | ② 기호만 있고 글자가 없음 |
| A17 | 지문 기호 탈자 | "㉠을 고르시오"라고 했는데 지문에 ㉠이 없음 |
| A18 | 지문 통째 없음 | "다음 문장을 읽고"라고 했는데 지문 자체가 없음 |

### 2단계 — AI가 묶음으로 검사 (그룹 프롬프트)

| 그룹 | 포함 오류 | 설명 |
|------|---------|------|
| G1 글자·표기 | A04 맞춤법, A05 영어 오자, A06 띄어쓰기 | 표기 규범 관련 오류 |
| G4 법령 | A09 틀린 법령명, A20 틀린 법령 조항 | 법령 인용 오류 |
| G5 편집 | A11 편집 메모, A14 정답 노출 | 출판 전 정리 안 된 흔적 |

### 3단계 — AI가 유형별로 정밀 검사 (개별 프롬프트)

| 코드 | 오류 이름 | 예시 |
|------|---------|------|
| A02 | 오자 | `외부` → `외뷰` (자모 변형) |
| A07 | 특수기호 누락 | 의문형 문장인데 물음표가 없음 |
| A08 | 어색한 문장 | 주어·서술어 호응이 맞지 않음 |
| A10 | 오자+보기 누락 복합 | 오자가 있으면서 선택지 내용도 없음 |
| A12 | 편집 메모 복수 | `[폐기][해설부족]`처럼 메모가 두 개 이상 |
| A16 | 탈자 | `합니다` → `함다` (글자 빠짐) |
| A19 | 법령 기호 누락 | 법령명에 「 」 기호가 없음 |
| A21 | 잘못된 단어 | 문맥상 틀린 단어 (예: `최대한` → `최소한`) |

## 성능 (V2 테스트 파일 기준)

| 비교 항목 | 기존 방식 (per-type) | **이 시스템 (hybrid)** |
|---------|-------------------|----------------------|
| AI 호출 횟수 | 630회 | **330회** |
| 비용 절감 | 기준 | **약 48% 절감** |
| 탐지 문항 수 | 23개/30문항 | **23개/30문항 (동일)** |
| 탐지 정확도 | 중간 (오탐 포함) | **향상 (오탐 감소)** |

> 호출 횟수를 절반으로 줄였는데도 탐지 문항 수는 동일합니다.  
> 오히려 컴퓨터 규칙으로 처리하는 구조 오류는 AI보다 더 정확합니다.

## 파일 구조

```
cert-poc/
│
├── data/                        ← 시험지 파일 (HWP, MD)
│
├── prompts/
│   ├── holistic/                ← 검출 코어 (review.md + system.md)
│   └── _shared/                 ← output_schema.json (11-enum findings)
│
├── src/
│   ├── hwp_parser.py            ← HWP → 텍스트 변환
│   ├── cli.py                   ← 파이프라인 CLI 어댑터
│   ├── hybrid_run.py            ← back-compat shim (cli.main 호출)
│   └── core/
│       ├── pipeline.py          ← holistic 검출 로직 (단일 소스)
│       ├── events.py            ← 진행 이벤트 계약 (web 미러)
│       └── parsing.py           ← 입력 → '## N.' Markdown
│
└── results/
    └── holistic/
        ├── Q01.json …           ← 문항별 검출 결과 (캐시/재개)
        └── results.json         ← 최종 집계
```

## 실행 방법

### 1. HWP 파일 파싱 (텍스트 변환)

```bash
python src/hwp_parser.py "data/시험지파일.hwp"
# → data/시험지파일.md 생성
```

### 2. AI 검수 실행

```bash
python src/cli.py --input "data/시험지파일.md"
# → results/holistic/ 폴더에 결과 저장 (문항당 holistic LLM 1콜)
```

### 3. 특정 문항만 검사

```bash
python src/cli.py --input "data/시험지파일.md" --q 13
# → 13번 문항만 검사
```

### 4. 웹앱 개발 서버 (FastAPI + Next.js 동시 기동)

리포지토리 루트에서 PowerShell 로 실행하면 백엔드/프론트가 각각 새 창에서 뜬다.

```powershell
.\run-app.ps1                       # API :8000 + WEB :3000 기동 (각 새 창)
.\run-app.ps1 -Install              # 최초 1회: .venv 생성 + 의존성 설치 후 기동
.\run-app.ps1 -ApiPort 8001 -WebPort 3001   # 포트 변경
.\run-app.ps1 -NoReload             # uvicorn 자동 리로드 끔
```

- API: `http://localhost:8000` (health `/health`, 문서 `/docs`)
- WEB: `http://localhost:3000` (→ `/sessions`)
- 백엔드 의존성은 `run-app.sh --install` / `run-app.ps1 -Install` 이 만드는 `.venv`
  안에 설치된다. Homebrew Python(PEP 668) 환경에서도 시스템 패키지를 건드리지 않는다.
- 프론트의 실서버 연결은 `web/.env.local` 의 `NEXT_PUBLIC_API_BASE` 로 제어한다
  (해당 파일을 지우거나 `NEXT_PUBLIC_USE_MOCK=true` 로 두면 목업 모드).
- 종료: 각 서버 창에서 `Ctrl+C`.

### 5. LLM 공급자 전환 (로컬 LLM ↔ Claude Haiku)

내부망 로컬 모델(EXAONE 3.5 32B 등)과 Claude Haiku 를 **토글**로 전환할 수 있다.
설정은 루트의 `.env`(템플릿: `.env.example`)에서 관리한다.

```dotenv
LLM_PROVIDER=claude                 # 기본 공급자: local | claude
LLM_MODEL=lgai-exaone/exaone-3.5-32b-instruct   # local 모델 ID
ANTHROPIC_API_KEY=sk-ant-...        # claude 사용 시 (셸 환경변수에 있으면 생략 가능)
CLAUDE_MODEL=claude-haiku-4-5
```

- **프론트엔드**: 사이드바 하단 / 업로드 화면 / 오류 화면의 토글로 분석마다 공급자를
  선택한다. 선택은 브라우저에 저장돼 새 분석·재실행에 이어 적용된다.
- **재실행**: 분석이 오류(예: 로컬 LLM 미연결)로 끝나거나 완료된 세션은 업로드 없이
  **재실행** 버튼으로 다시 돌릴 수 있다 — 공급자를 Claude 로 바꿔 재시도하는 용도.
- **CLI**: `python src/cli.py --input data/파일.md --provider claude`
- ⚠️ `.env` 의 `ANTHROPIC_API_KEY` 를 바꾼 뒤에는 **API 서버를 재시작**해야 한다
  (uvicorn `--reload` 는 `.py` 만 감시하고 `.env` 는 감시하지 않는다).

## 시스템 요구사항

| 항목 | 내용 |
|------|------|
| Python | 3.10 이상 |
| Node.js | 18 이상 (HWP 파싱용) |
| LLM 서버 | 로컬 모델 서버 (포트 8081) |
| 운영 환경 | 폐쇄망(인터넷 불필요) 동작 가능 |

> 시험지 보안을 위해 외부 AI API(ChatGPT 등)를 사용하지 않습니다.  
> 모든 AI 처리는 내부 서버에서만 이루어집니다.

## 개발 배경

시험지 제작 과정에서 교정 담당자가 수백 문항을 손으로 검토하는 데 많은 시간이 소요됩니다.  
특히 비슷해 보이는 오류(오자·탈자·맞춤법)나 구조 오류(선택지 개수, 지문 누락)는  
피로한 상태에서 놓치기 쉽습니다.

이 시스템은 **사람 검수를 대체하는 것이 아니라, 검수자가 중요한 판단에 집중할 수 있도록**  
반복적이고 기계적인 확인 작업을 자동화하는 것을 목표로 합니다.
